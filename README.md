"EMoDo" (Electric Motor Doctor) is a project which is perfect mixture of Machine Learning and Electrical Engineering. 

Problem aiming to solve : The heavy industrial motors especially Permanent Magnet Synchronous Motors are have the spinning rotor which when runs at a certain speed,the winding gets heated and this leads to the demagnetization of the permanent magnets. This demagnetization reduces the efficiency of the motor and might also even break down on some random Friday evening.

Solution : To solve this problem it might feel that attaching a thermal sensor to detect the temperature is a smart move. But practically it is not possible , as the sensor has to be attached to the permanent magnet winding and even if we attach it the sensor it will get detached or disconnected at the starting of the motor itself .So instead of measuring the temperature we calculate it. The above project is trained ,tested and evaluated on an experimental of the Permanent Magnet Synchronous Motors from The Paderborn University, Germany from kaggle datasets. In the project there are a lot of factors which directly or indirectly affect the temperature of the Permanent Magnet Synchronous Motors.Some of them include Stator Yoke Temperature,Motor Speed,Current and Voltage  supplied etc.So using all of them and the Permanent Magnet Synchronous Motor temperature column, I tried to use Machine Learning and predict the temperature of the Permanent Magnet Synchronous Motors.

How this project can be made instantly deployable : We can use TinyML(Tiny Machine Learning) and run the model locally on microcontrollers and integrate it with sensors only at those places where measurement of the physical quantity is possible like current, voltage, motor speed etc and the ML model  will predict the values of the physical quantity which are not possible to measure practically .We can also add a buzzer, program it to beep a particular number of times for different situations. For example if critical temperature is 120 degree celsius then we can program it to beep for twice when the temperature is 90 degree celsius and might beep repeatedly when it reaches 100 degree celsius.

During the beginning of creating the model when I fitted a RandomForestRegressor for the dataset, my laptop took a lot of time to respond with a score of 99.96% accuracy. I was glad after looking at this but in Machine Learning if a model performs really well then something's fishy. The data was getting leaked. So I implemented GroupKFold validation .I got an accuracy of 81%. Time to evaluate. When I checked for Mean Absolute Error and Max Error I found them to be 5.85 and 71.81 respectively which was shocking. Then I did a bit of research found the reason which is because of a tiny portion of bad data or corrupted data. I had a glance at the prediction values and actual values, cleaned it. When I did so I got merely 3 rows out of 1.3 million rows that were considered as corrupted data which is just 0.00023%.Now the  Mean Absolute Error and Max Error were 5.5 and 40.59.This concludes that for every prediction there's a chance of getting the predicted value 5.5 degree celsius more or less than actual values and out of 1.3 million cycles only once the model might predict the temperature of the spinning rotor, that might have a difference of 40.59 degree celsius.
